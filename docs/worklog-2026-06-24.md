## 1. Reliability & "Nova watches Nova"

The headline theme: **build outran maintenance** — several things had silently died with
nobody paged. We fixed the instances and built the backstop.

- **Smart-plugs power dashboard fixed** — graphs had gone flat. Root cause was *not* the
  dashboard: the `nova_zigbee_energy_bridge` had been holding a **dead Postgres connection
  for 4 hours**, silently swallowing every insert (psycopg2 only flags `.closed` on a
  client-side close; a server-side drop looks "open"). Restarted it and **hardened it to
  reconnect-on-drop** so a transient PG blip costs one reading, not a multi-hour blackout.
- **#510 — core-liveness gate ("Nova watches Nova").** New standalone daemon
  `nova_core_liveness.py` (launchd, deliberately *not* under the scheduler it watches).
  Every 120s it: (1) independently TCP-probes 7 keystones (PG, pgbouncer, redis,
  memory-server, gateway, scheduler, inference-router); (2) **watches the watchers** —
  alarms if `health_checks` or `capacity_snapshots` go stale (the exact silent-death signal
  that started the MNB epic); (3) cross-checks each keystone's health status. On failure it
  pages `nova_notify` at **level=critical** (outside the Big Brother digest path) and files a
  deduped priority-1 incident. Verified clean-run + injected-failure.
- **#697/#698/#703 — Ollama GPU contention incidents** — investigated; transient compute
  spikes during concurrent model loads. Verified healthy across light + heavy models, 97%
  memory free. No reboot needed. Flagged **#428 (reboot for stuck Metal) as likely stale**.
- **#508 — incidents weren't auto-closing.** Root-caused: there are **two incident tables** —
  `nova_incident_lifecycle.py` only manages `telemetry.incidents` (works fine); the stale
  ones live in `public.incidents` (Big Brother/Wazuh), which nothing auto-closes. Cleared the
  unambiguous dead-hardware/restored-service ones; **left 5 recent nova-core security
  correlations open for review** (deliberately did not auto-close security incidents — that
  would re-introduce the slow-burn masking #510 exists to prevent). Auto-close *policy* left
  for Little Mister.
- **#644 — backups that actually restore.** `nova_pg_backup.sh` now auto-discovers ALL user
  DBs (was nova_memories-only); added a monthly restore-test drill (`nova_backup_restore_test.py`).
- **#645 — config-as-code + drift detection.** PG-backed `nova_config_drift.py` snapshots all
  launchd plists, `--bless` sets the baseline, default run alarms on modified/untracked/missing.
  Re-blessed after each plist change (now 99 plists).
- **Alerting overhaul** — added retry/confirmation before paging + made the affected host
  prominent across the monitoring + Grafana stack.
