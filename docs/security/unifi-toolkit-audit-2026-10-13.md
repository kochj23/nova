# Security Audit: Crosstalk-Solutions/unifi-toolkit v1.13.1 (commit 24add95)

Audit date: 2026-10-13. Method: static review of the shallow clone only. No scripts, tests, setup/upgrade scripts or requirements were executed or installed. The only code run was `python3 -I` against the standard library (`ipaddress`, `urllib.parse`, `socket`, `yarl`) to confirm parser behaviour, from a directory outside the repo and without importing any repo code.

## Summary verdict

**Fine on a single-user trusted LAN with `DEPLOYMENT_TYPE=production`. Not safe in its default local mode on any network you don't fully trust. Don't expose it beyond the LAN without HTTPS through Caddy and a firewalled port 8000.**

The code is careful in a lot of places:
- no raw SQL
- consistent output escaping (Alpine `x-text`, `escapeHtml`, Jinja autoescape)
- a strict marker-and-`predefined` guard before House Arrest deletes a firewall policy
- dry-run defaults on destructive House Arrest calls
- a reasonable anti-DNS-rebinding Host check
- bcrypt login with a rate limit
- Fernet at rest
- the container runs as a non-root user

The material risks come from the defaults and the architecture:

1. **The default deployment (`DEPLOYMENT_TYPE=local`) has no authentication and listens on `0.0.0.0:8000`.** The process holds UniFi admin credentials and can rewrite firewall policies, DHCP DNS servers, WLAN isolation and client blocks. Any host that can reach port 8000 gets that power. It is also reachable cross-site from any web page the operator visits (CSRF and WebSocket hijacking), because local mode skips every check.
2. **TLS verification to the controller is off by default.** The admin password or API key is sent to whoever answers on the LAN.
3. **The webhook SSRF filter can be bypassed** with IPv4-mapped IPv6 literals and `[::]`, by following redirects, and through the DNS check/connect TOCTOU.
4. **Supply chain:** floating CDN script versions (`alpinejs@3.x.x`, unversioned `chart.js`), no SRI and no CSP, on a page that controls the firewall.

### Areas checked and found sound
- **Production auth.** Fails closed when `AUTH_PASSWORD_HASH` is empty (bcrypt raises, so the result is False). Cookie flags are `HttpOnly; Secure; SameSite=Lax`. The token is 256 bits from `secrets`.
- **Production CSRF.** The `X-Requested-With: XMLHttpRequest` check covers every `/api/` prefix. All routers use an `/api` prefix (verified). There is no CORS middleware, so a cross-origin custom header fails preflight. Together with SameSite=Lax this is adequate.
- **Anti-rebinding Host check** (`app/main.py:189-268`). It correctly refuses attacker hostnames over HTTP. It does not cover WebSockets (UT-03), and IP-literal Hosts don't stop plain CSRF (UT-02).
- **UniFi credentials are never returned by any API.** Each save replaces the credentials together with the URL, so the controller URL can't be repointed at an attacker while the stored credentials stay in place.
- **House Arrest deletion guard.** `predefined` policies are never deleted. Explicit IDs that lack the marker are refused and reported. A release without a label is refused for device lockdowns. Dry-run is the default for lockdown, release, DNS lockdown and dhcp-dns. BLOCK ACLs are deleted before their ALLOWs, and the release stops if a BLOCK fails.
- **Docker.** Runs as a non-root user (uid 1000) in a multi-stage build. HSTS is set in Caddy. The app sets nosniff, `X-Frame-Options: SAMEORIGIN` and Referrer-Policy. There is no CSP (UT-09).

## What Nova should copy / must avoid

This section is for a team reimplementing Wi-Fi Stalker, Threat Watch and House Arrest as headless Python scripts that write to Postgres. There is no web UI, so UT-02, UT-03, UT-09, UT-21, UT-23 and UT-28 disappear. Everything to do with the controller, credentials, webhooks and firewall safety carries over.

### Copy
1. **House Arrest's safety model, then make it stronger:**
   - Never touch a policy with `predefined: true`.
   - Tag every created object (`[HouseArrest]` in `description`).
   - Default to dry run.
   - Refuse unscoped "release everything".
   - Delete BLOCK before ALLOW, and stop on the first failed BLOCK delete.
   - Create the ALLOW first, then verify ordering after creation (`dns_order_is_safe`).
2. **Verify writes by re-reading.** Poll after a PUT; never trust `200 {"rc":"ok"}` (`unifi_client.py` `_write_network`). UniFi's async provisioning makes this necessary.
3. **Keep one long-lived controller session per process** (`shared/unifi_session.py`), so that username/password controllers don't trip fail2ban. Prefer an API key over a password.
4. **Pure-function policy builders** with no I/O (`tools/house_arrest/policies.py`), so payloads can be unit-tested without a console.
5. **Validate webhook URLs at save time and again at send time.** The idea is right; implement it properly (see Avoid #4).
6. **`_FILE` secret indirection** (`run.py:19-51`). Map it to macOS Keychain or another secret store instead of env vars.
7. **Normalise MACs strictly** (`normalize_mac`), and match device presence on normalised MACs.

### Avoid
1. **Any unauthenticated control path.** A headless script still needs its trigger (Slack command, queue row, cron) to be authenticated and authorised. Don't let "write a row to `claude_queue`" become "anyone with DB write access can lock down the network". Keep firewall-mutating actions behind an explicit allow-list of requesters and an audit row.
2. **`verify_ssl=False`.** Pin the console's certificate fingerprint (TOFU, stored in Postgres or Keychain) and fail closed on mismatch. Don't accept `http://` controllers. Don't put the API key in session-default headers; disable redirects on controller calls.
3. **Marker-only ownership.** Write a Postgres ledger table for every object created or changed (controller `_id`, kind, label, created_at, the full payload sent, and a before-snapshot for modified network, WLAN or site docs). Delete only IDs in the ledger that still carry the marker and are not predefined. Use unique labels, or IDs instead of names, for ACLs (avoid the 32-character truncation collision in UT-12).
4. **The webhook SSRF filter as written.**
   - Resolve once.
   - Reject anything where `not ip.is_global`, after unwrapping `ipv4_mapped`, 6to4 and NAT64.
   - Connect to the vetted IP.
   - Set `allow_redirects=False` and a short timeout.
   - Don't log full URLs.
   - Store webhook URLs encrypted, or in Keychain.

   Simpler still: for Slack, use the existing Nova Slack integration rather than arbitrary URLs.
5. **Unvalidated IDs and values sent to the controller.** Check `^[0-9a-f]{24}$` for `_id`s, `ipaddress` for resolvers, and an enum for presets. Quote path segments.
6. **Whole-document read-modify-PUT without a concurrency check.** Re-read immediately before the PUT, diff only the intended fields, and abort if anything else changed since the snapshot.
7. **Secrets in logs.** No connection strings, URLs with tokens, or raw controller error bodies at INFO level. Keep the encryption key separate from the data (Keychain, not a file next to the DB).
8. **Self-lockout.** Before any lockdown, refuse MACs belonging to the gateway, the host running Nova, and a configured "never lock" list (no such guard was found in `/lockdown`).
9. **Floating dependencies.** Pin with hashes; this matters more for an unattended process holding firewall credentials.
10. **Treat all controller data as untrusted:** hostnames, SSIDs, IDS signatures and AP names (clients set their own hostnames). Use parameterised SQL in Postgres (psycopg parameters, never f-strings), and escape it when it is relayed into Slack mrkdwn (`<!channel>`, `<@U…>`) or LLM prompts. Nova's chat agent consumes this data, so a crafted DHCP hostname is a prompt-injection vector.
